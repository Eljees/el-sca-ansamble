## 2. Что осталось открытым (фактическое состояние на сейчас)

### 2a. Блокеры завершения batch (12104 + 12080)

- **Прогон ещё не завершён.** На 2026-05-17 в `D:\__tests\_SCA\` лежит свежий отчёт только за 12103. У 12104 и 12080 — отчёты от 2026-05-15 (старые, идентичные по содержанию = битые).
- **Что должно отработать после исправлений 5.10 + 5.11:**
  - 12104 (Windows-installer ZIP): auto-detect `Format=win` → innoextract → `win-analyzer` собирает SBOM → grype-on-SBOM → cve-bin-tool binary scan. Прошлый запуск падал на `Clean` от вчерашнего `app.\` мусора; теперь Clean через docker, мусор будет снят.
  - 12080 (Android APK ZIP): auto-detect `Format=apk` → `apk-analyzer` (extract APK + synthesize SBOM) → grype-on-SBOM. Этот pipeline ни разу за сессию не запускался — может вскрыться следующий блокер.

### 2b. Известные «не блокирует, но раздражает»

- **Шапка отчёта частично UNKNOWN.** `reporting.py:303-306` читает `status.json` / `summary.json` / `run_manifest.json` / `db_snapshot.json` из `artifacts/`, но **их никто не пишет**. В шапке любого отчёта — `DB snapshot: UNKNOWN`, `DB drift: UNKNOWN`, `Tool failures: UNKNOWN`, `Update policy: grype=UNKNOWN`. Не блокирует, но обесценивает шапку. Открытая задача в plan'е #22.
- **cve-bin-tool 3.4 traceback на `version_string = UNKNOWN`.** При SBOM с компонентом, у которого `version=UNKNOWN`, scanner кидает `UnknownVersion` exception. Wrapper'ом ловится через `[ "$scan_rc" -le 1 ]` → report.json создаётся. Но traceback в логах сбивает с толку. Лечится фильтром компонентов перед `--sbom-file`.
- **No-update-by-default не enforced.** `cve-bin-tool-updater` / `grype-updater` / `trivy-updater` имеют `profiles: [..., default, ...]`. Чистый `docker compose up` (без `--profile`) поднимет updater'ы и попробует ходить в NVD. Открытая задача в plan'е #24.
- **`offline` profile противоречит своему имени** — там же сидят `grype-updater` и `cve-bin-tool-updater`. Это исторический баг; правильно — оставить только в `update`/`default` или вынести из `offline` совсем (паттерн `airgap` уже сделан корректно).
- **Новые модули не покрыты тестами**: `scanner_diff.py`, `enrichment.py`, `proxy_chain.py`. Grep по `tests/` не нашёл `test_scanner_diff` / `test_enrichment` / `test_proxy_chain`. Их легко сломать любым рефакторингом.

### 2c. Локальные WSL/Yandex Disk-эффекты, влияющие на наблюдаемость

- Yandex Disk → WSL bind-mount периодически отдаёт устаревший снимок `artifacts/` (см. сегодняшние эпизоды, когда я видела вчерашние логи updater'а). На самом продукте это не влияет, но мешает мониторить прогон со стороны.

## 3. Узкий план: «дотянуть batch»

Сфокусирован на единственной цели — получить три валидных свежих отчёта 12103/12104/12080. Hardening и тесты вынесены отдельным P-постфиксом для последующих итераций.

### Фаза D1 (Delta-1) — повторный прогон с уже сделанными фиксами

| # | Действие | Кому |
|---|---|---|
| D1.1 | Подтвердить, что текущий batch завершился (или прерван). | пользователь, `Get-ChildItem 'D:\__tests\_SCA' -Filter '*_report_2026-05-17.md' -Recurse` |
| D1.2 | Если 12104 и/или 12080 нет — повторно запустить блок из последней моей команды (`Set-Location` + `$env:COMPOSE_FILE` + foreach с try/catch). DB **не** обновлять. | пользователь |
| D1.3 | Я опрашиваю `artifacts/` и `D:\__tests\_SCA\` каждые 40 сек, ловлю первый же ненулевой exit. | я |
| D1.4 | По итогу — summary блок (Syft components / Grype findings / cve-bin-tool / severity counts) для всех трёх кейсов. | я, один Read на каждый MD |

### Фаза D2 (Delta-2) — точечные фиксы, только если D1 выявит новые блокеры

Каждый item — отдельный 5–15-минутный коммит, отдельный TaskCreate. Делаем только при наступлении симптома.

| Возможный симптом | Фикс |
|---|---|
| `win-analyzer` не находит exe внутри zip | Расширить magic-byte detection в `scripts/analyze_win_installer.py` |
| `innoextract` снова даёт NTFS-illegal имена | Подменить extract-output на named volume (как сделано для `extracted-staging` в `windows.override`) |
| cve-bin-tool бинарный скан > таймаут на большом MSI | Поднять `CVE_BIN_TOOL_SCAN_TIMEOUT_SECONDS=3600` в env строкой `$env:CVE_BIN_TOOL_SCAN_TIMEOUT_SECONDS='3600'` перед вызовом |
| `apk-analyzer` падает на signed-zip APK | Проверить, что zip обёртка распаковывается до `.apk`, потом передаётся в androguard |
| Любой scanner возвращает пустой report.json | Не блокер: `collect_reports.sh:_ensure_report` создаёт `[]`-плейсхолдер, отчёт собирается с Consistency warning |

### Фаза D3 (Delta-3) — финализация артефактов

| # | Действие |
|---|---|
| D3.1 | Все три отчёта сегодняшней датой в своих CYBERSEC-папках, шапка содержит правильный CASE_ID (auto-detected из пути; параметр `-CaseId` уже работает). |
| D3.2 | Postfix-блок (regex-replace `^# CYBERSEC-\d+:` на правильный) больше не нужен — CASE_ID теперь честный. Если кейс не вычисляется из пути — шапка будет `CYBERSEC-UNKNOWN`, см. `docs/windows-powershell.md` §3. |
| D3.3 | Старые `_report_2026-05-15.md` рядом с теми же tarball'ами оставить как есть (исторический мусор), при желании удалить вручную. |

**Acceptance** для всей delta-итерации:

```text
D:\__tests\_SCA\CYBERSEC-12080\iDocs11c2781f2-android-build-release-signed_report_2026-05-17.md  ← собранный через apk-analyzer
```

Все три файла:

- Шапка `# CYBERSEC-1210X: konteynernyy SCA-otchet`.
- `Scanner summary` имеет ненулевой `Syft components` хотя бы один раз.
- Раздел `High / Critical findings` либо содержит таблицу, либо явно сообщает «не обнаружены».

## 4. Что вынесено за рамки этой итерации (вернёмся отдельно)

Эти пункты остаются открытыми, но не обязательны для D-цели «три валидных отчёта». Все они уже зафиксированы как задачи в треке.

- **No-update-by-default policy hardening** (#24). Убрать `default` из `profiles` у `*-updater` сервисов, добавить «`-UpdateDb` — внимание!»-warning в `run-scan.ps1`, обновить `docs/runbook.md` про новый дефолт.
- **status.json / summary.json / run_manifest.json / db_snapshot.json** (#22). Чтобы шапка отчёта перестала быть `UNKNOWN`. Простейший путь — `collect_reports.sh` собирает эти 4 файла из доступных artefacts перед вызовом `collect-report`.
- **Тесты для новых модулей** — `test_scanner_diff.py`, `test_enrichment.py`, `test_proxy_chain.py`. Минимум один happy-path + один failure-path на каждый.
- **Профиль `offline` vs `airgap` дисциплина**. Сегодня `offline` оставляет `grype-updater` и `cve-bin-tool-updater` — это путает: либо переименовать `offline` в `mixed-update`, либо убрать updater'ов из `offline`. Документация уже частично говорит про `airgap` (`docs/airgap.md`).
- **cve-bin-tool 3.4 traceback на `version=UNKNOWN` в SBOM**. Препятствие — баг upstream'а. Workaround в `update_cve_bin_tool.sh`: фильтровать компоненты с `version=UNKNOWN` из `cyclonedx.json` перед `--sbom-file`.
- **CI: pre-commit / GitHub Actions**. Хуки и пайплайн уже описаны в `PLAN_2026-05-16.md` Phase 4; здесь не повторяю.
- **Документация для batch-workflow** (когда нужно прогнать N кейсов подряд). Сейчас blob-paste из чата; место — `docs/operations.md` §«batch processing».
