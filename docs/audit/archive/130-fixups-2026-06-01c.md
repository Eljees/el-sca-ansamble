## 2. New findings

### 2.1 `_normalize_severity` duplicated in `reporting.py` and `scanner_diff.py` (P4, SMELL)

Both modules define an identical 3-line helper:

```python
def _normalize_severity(value: Any) -> str:
    if not value:
        return "UNKNOWN"
    return str(value).upper()
```

This escaped the `_io.py` consolidation because it is domain-specific (not a
hash/JSON helper). It is too small to warrant a new shared module; moving it
to `_io.py` would be semantically odd. The duplication is acceptable at this
size — document and defer.

**Recommended future action:** if a third module needs this helper, move it
to a new `resilient_updates/_scan_helpers.py` shared module at that point.

### 2.2 `reporting.py` — thin unit-test coverage (P3, SMELL)

`reporting.py` is 538 lines with one test (`test_build_report_includes_hashes_and_db_metadata`).
The single test is a good end-to-end integration test for `build_report`,
but the 15+ helper functions (`_grype_findings`, `_trivy_findings`,
`_cve_bin_tool_findings`, `_build_db_metadata_table`, etc.) are only exercised
transitively. A schema change in one of the scanner output formats could
break a helper silently if the end-to-end test's fixture doesn't exercise
that path.

**Recommended future action:** add parametrized unit tests for
`_grype_findings`, `_trivy_findings`, and `_cve_bin_tool_findings` covering
empty input, malformed input, and a sample with one finding each. Estimated
40–60 lines.
