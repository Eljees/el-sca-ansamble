## 0. Суть проекта и текущие приоритеты

**el-sca-ansamble** — контейнерный SCA-комплекс для безопасности программного обеспечения.
Оборачивает Trivy, Grype, Syft, cve-bin-tool в Docker с Python-оркестрационным слоем
(`resilient_updates/`). Ключевые возможности: SBOM + отчёт об уязвимостях в Markdown/HTML,
air-gap развёртывание, Windows-установщики (win-analyzer), Android APK (apk-analyzer),
fallback-цепочка источников с retry/provenance.

**Текущий статус:** 617 тестов, все проходят. 90% покрытие. ruff 0 ошибок. Git чистый.
17 коммитов не запушены в GitLab.

## 5. Архитектурные замечания

### 5.1 Точки входа — документация актуальна

`scripts/README.md` уже содержит корректное описание всех скриптов:
- `run-scan.sh` (dash) — основной Linux runner
- `scan_archive.sh` — "mostly superseded by `run-scan.sh`; kept for backward compatibility" ✅
- `run_scan.sh` (underscore) — per-tool native wrapper, не дублирует

`docs/audit/10-defects.md:127` подтверждает: `run_scan.sh` (underscore) — **не дефект**.

### 5.2 `docs/architecture.md` — один пробел

Таблица профилей имеет 14 записей. Отсутствует `db-bundle` (сервисы `db-exporter` и
`db-importer` для экспорта/импорта DB-бандлов). Всего в compose: **15 профилей**.

**Fix:** добавить строку `| \`db-bundle\` | Экспорт/импорт DB-бандлов | db-exporter, db-importer |`

### 5.3 `requirements.txt` — unpinned

`pip-compile` не запускался. `requirements.in` есть, но `requirements.txt` содержит loose
constraints (`>=`). В CI каждый build тянет latest compatible.

**Fix (Elaria):** `make lock` → `pip-compile --generate-hashes -o requirements.txt requirements.in`

### 5.4 `.gitlab-ci.yml` — существует, не использован в полной мере

Файл есть, зеркалирует `.github/workflows/ci.yml`. Но **17 коммитов не запушены** →
CI на GitLab не валидирует последние изменения. Особенно критично — D-NEW-1 (py3.10 compat)
закрыт локально, но не подтверждён CI-матрицей на 3.10/3.11/3.12.

### 5.5 `cli scan` subcommand (ADR-0005) — не выставлен

`orchestrator.py` создан, `cli.py` имеет `scan` subparser, но в `README.md` и
`docs/operations.md` `cli scan` как unified entrypoint не задокументирован.
Пользователь по-прежнему видит только `run-scan.sh` как точку входа.
