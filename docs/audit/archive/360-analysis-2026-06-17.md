## 2. Что было сделано после 350-analysis (1 коммит)

| Коммит | Дата | Тип | Содержание |
|---|---|---|---|
| `d4065cd` | 17.06 | fix(update-db) | grype/trivy SOCKS-proxy bug: HTTPS_PROXY не выставляется из HTTP-маршрута cve-bin-tool; `_load_dotenv` в orchestrator |

### Детали d4065cd

**Причина 1** — `render_env()` в `route_plan.py` выставлял `HTTPS_PROXY=http://host:PORT`
из маршрута cve-bin-tool глобально. Go's `net/http` отдаёт приоритет `HTTPS_PROXY`
над `ALL_PROXY` → grype/trivy пытались HTTP CONNECT на SOCKS5-порт → провал.

**Фикс**: `http_url` берётся только из trivy/grype (не из cve-bin-tool). Новый тест:
`test_render_env_socks_only_host_no_https_proxy`.

**Причина 2** — `orchestrator.start_update()` и `_run_scan()` строили `env = dict(os.environ)`,
который не читал `.env` файл (его читает только `docker compose`, не Python).

**Фикс**: хелпер `_load_dotenv(env, repo_root / ".env")` в обоих местах. Shell-переменные
имеют приоритет.

### N7-4 (INFO) — FUSE stale-mount: воспроизводимый паттерн

На этом стенде FUSE-mount устаревает после записи файлов через Edit/Write инструменты.
Симптомы:
- `git diff HEAD` в sandbox показывает файлы как truncated (page-кеш ≠ реальный NTFS)
- pytest/ruff в sandbox используют stale `.pyc` или усечённые источники
- Read tool (обходит FUSE → Windows API) показывает реальный контент

**Митигация:** всегда использовать Read tool для верификации, коммитить через
Desktop Commander (`shell: cmd`), не доверять `ruff check` в sandbox для файлов
изменённых ранее 15 минут.
