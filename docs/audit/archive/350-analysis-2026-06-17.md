## 0. Суть проекта (краткий ориентир)

**el-sca-ansamble** — контейнерный SCA-комплекс (Trivy, Grype, Syft, cve-bin-tool)
с Python-оркестрационным слоем (`resilient_updates/`). Выпускает SBOM +
отчёты об уязвимостях (MD/HTML). Возможности: air-gap, Windows, Android APK,
fallback-цепочка источников, route-doctor, GUI-дашборд, proxy-chain, checkpoint+resume,
heartbeat, монитор, near-source artifact mode, one-command bootstrap.

```

```

`artifacts/` — ожидаемо (gitignored runtime-артефакты, последний прогон 2026-06-14–15).

**`run-scan.ps1` (M):**  
`git diff scripts/windows/run-scan.ps1` вернул только предупреждение:
```
warning: in the working copy of 'scripts/windows/run-scan.ps1', LF will be replaced by CRLF
```
Фактического diff нет. Это CRLF-артефакт Windows (`core.autocrlf`): рабочая копия
содержит LF, но git ожидает CRLF на этой платформе. Контент файла идентичен
закоммиченной версии. Реальных изменений нет.

**Рекомендуемое действие:** `git checkout scripts/windows/run-scan.ps1`
(сбросит CRLF-состояние без потери данных).

## 5. Новые наблюдения

### N6-1 (INFO) — server.py:675 mcp.run() был no-op, теперь исправлен

Незаметный, но важный баг: в `4e81b95` исправлен `mcp.run()` (был `mcp` без вызова).
Это означало, что MCP-сервер не запускался при выполнении `server.py` напрямую.
Исправлено корректно; тесты `test_docker_mcp_server.py` остались зелёными.
Дополнительного внимания не требует.

### N6-2 (P2) — Нет теста для «Fixed in» колонки в reporting.py

`2bf9fea` изменил `reporting.py` на 17 строк (новая функция извлечения `fix_versions`
из grype JSON и `FixedVersion` из trivy JSON). Проверить:
- `tests/test_reporting.py` (или аналог) — покрывает ли он новую колонку?
- Есть ли фикстуры grype/trivy с непустым `fix.versions`?

**Риск без теста:** регрессия в формате таблицы при следующем изменении reporting.py
может остаться незамеченной до ревью вывода.

**Способ устранения:** добавить 1–2 параметризованных теста: grype-находка с
`fix.versions: ["1.2.3"]`, trivy-находка с `FixedVersion: "2.0.0"`, проверить
наличие колонки и значения в итоговом markdown.

### N6-3 (P2) — Версия v0.1.3 устарела: 11 коммитов после тега

С тега `v0.1.3` (2026-06-13) накоплено 11 коммитов, включая:

### N6-4 (INFO) — grype timeout 30с→300с (43e2399)

Увеличение в 10× — значит реальные сети требуют >30с для скачивания grype DB.
Это правильно для корпоративных прокси. Но при прогоне с обновлением в CI
каждая попытка теперь ждёт до 5 минут. Если CI использует временной лимит
на шаг, это может вызвать нежданный таймаут CI при сетевых проблемах.
Флаг `EL_SCA_GRYPE_UPDATE_TIMEOUT` для переопределения через .env — хорошая идея
для CI-нужд.

### N6-5 (INFO) — run-scan.sh: run_stage_soft добавляет ~36 строк (208bdd1)

Функция `run_stage_soft` повторяет паттерн `run_stage` с пропуском на ненулевом exit.
В будущем если появится больше soft-fail стейджей — стоит параметризовать
(например, `run_stage NAME CMD [--soft]`). Пока нормально, флаг для backlog.

### N6-6 (INFO) — docs/audit/archive/ растёт: 26 файлов (май–июнь 2026)

Архив будет только пополняться. При следующем масштабном рефакторинге или выходе
v0.2.0 стоит переложить файлы до 2026-06 в подпапку `archive/pre-v0.1.3/`
(или `archive/2026-Q2/`). Пока не срочно.
