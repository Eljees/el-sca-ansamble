### 1.2 Bug fixes in the new additions

**`atomic_publish._replace_tree` — staging rename bypasses monkeypatch**

The new code used `staging.replace(dst)` for the intra-volume rename after
a cross-device copy. Tests monkeypatch `Path.replace` to inject `EXDEV`.
This caused the staging→dst rename to re-raise `EXDEV` even though
staging and dst were on the same volume, making the cross-device fallback
path impossible to test correctly.

Fix: use `os.rename(staging, dst)` directly — the intent is explicit and
avoids the monkeypatch.

**`fallback.fetch_bytes` — SOCKS proxy intercepts localhost during tests**

`build_session()` wires `ALL_PROXY=socks5h://localhost:1080` into
`sess.proxies`. When the test suite spins up a mock feed server on
`127.0.0.1`, every request goes through the SOCKS proxy instead of
direct — the mock server never receives the connection.

Root cause: `requests` `no_proxy` in `sess.proxies` prevents *new*
proxy env-vars from being applied but does not clear already-set entries.
`should_bypass_proxies()` correctly identifies bypass candidates but
the session-level proxy overrides it.

Fix: in `fetch_bytes()`, call `should_bypass_proxies(url, no_proxy=…)`;
if True, pass `proxies={"http": None, "https": None}` per-request to
explicitly clear the session proxy for that call.

```python
_no_proxy = (
    sess.proxies.get("no_proxy")
    or os.environ.get("NO_PROXY")
    or os.environ.get("no_proxy")
)
from requests.utils import should_bypass_proxies as _bypass
_req_proxies: dict[str, str | None] | None = (
    {"http": None, "https": None} if _bypass(url, no_proxy=_no_proxy) else None
)
response = sess.get(url, timeout=timeout, headers=headers, proxies=_req_proxies)
```

**`scanner_diff.diff_runs` — duplicate findings inflate diffs**

### 1.4 `datetime.UTC` py3.10/py3.12 compat shim

The project targets Python 3.12 (production Docker, `.ruff.toml`
`target-version = "py312"`). `datetime.UTC` is py3.11+. The CI/test
sandbox runs Python 3.10, causing `ImportError` on collection for 11
test files and `AttributeError` for 3 more.

Fix: compat shim added to all 11 affected modules (9 production + 1 test
+ `analyze_apk.py` script):

```python
try:
    from datetime import UTC  # py3.11+
except ImportError:
    from datetime import timezone as _tz
    UTC = _tz.utc  # noqa: UP017
```

`enrichment.py` (uses `import datetime` module-style) gets a module-level
`_UTC` alias instead:

```python
try:
    _UTC = datetime.UTC
except AttributeError:
    _UTC = datetime.timezone.utc  # noqa: UP017
```

Result: **242/242 tests pass** on py3.10 sandbox; ruff reports zero
errors (UP017 satisfied by the `UTC` alias on the happy path).
