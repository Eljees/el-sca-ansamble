## 2. Changes applied in this pass

### 2.1  `.gitignore` — runtime JSON artifacts (NEW-1)

**Problem.** `artifacts/cache/*`, `artifacts/reports/*`, etc. were all excluded,
but `artifacts/*.json` (flat files at the root of `artifacts/`) were not.
`run_manifest.json`, `status.json`, `summary.json`, `db_snapshot.json` are all
runtime outputs written by `resilient_updates.run_summary` and
`resilient_updates.manifest`. Running the stack and then doing `git add .` would
silently commit them.

**Fix.** Added at the end of the `artifacts/` block in `.gitignore`:
```
artifacts/*.json
```

---

### 2.2  `docker-compose.yml` — use `${…_VERSION}` variables (NEW-2)

**Problem.** `versions.env` was created in phase F as the single source of truth
for scanner image tags, but all five image references in `docker-compose.yml`
still contained literal tags (`aquasec/trivy:0.64.1`, etc.).

**Fix.** Five `image:` lines now read:

```yaml
image: aquasec/trivy:${TRIVY_VERSION:-0.64.1}       # ×2
image: ghcr.io/anchore/grype:${GRYPE_VERSION:-v0.112.0}   # ×2
image: ghcr.io/anchore/syft:${SYFT_VERSION:-v1.20.0}      # ×1
```

The `:-fallback` syntax means the compose file still works without sourcing
`versions.env` — the default matches the value in that file.

### 2.4  Dockerfiles — non-root `USER` (§9)

**Problem.** All five `Dockerfile.*` ran their process as `root`, violating the
principle of least privilege and common container hardening baselines (CIS Docker
Benchmark 4.1).

**Fix.** Added a `RUN useradd` + `USER` pair to each Dockerfile:

- `Dockerfile.resilient-updater` → user `appuser`, UID 1001, workdir chown
- `Dockerfile.cve-bin-tool` → same pattern, plus `/opt/cvebt-cache`
- `Dockerfile.extractor` → same pattern
- `Dockerfile.apk-analyzer` → user `appuser`, UID 1001, workdir `/workspace`
- `Dockerfile.win-analyzer` → same pattern

The `pip install` cache mounts (`/root/.cache/pip`) are changed to
`/home/appuser/.cache/pip` to remain functional after the user switch.

### 2.5  `enrichment.py` — `mtime` as ISO-8601 string (§16)

**Problem.** `date_value = candidate.stat().st_mtime` stored a raw Unix
timestamp float (e.g. `1748271600.0`) in the `"mtime"` field of each EPSS
record. Downstream consumers expecting a date string (e.g. `reporting.py`)
would receive a float and either crash or silently misformat it.

**Fix.** Converted with:
```python
import datetime
date_value = datetime.datetime.fromtimestamp(
    candidate.stat().st_mtime, tz=datetime.timezone.utc
).isoformat()
```
The value is now a string like `"2026-05-26T09:00:00+00:00"`.

## 3. Remaining user-action items

### 3.1  NVD API key rotation (NEW-5) — **required before pushing**

`.env.local` contains `NVD_API_KEY` and `NVD_API_KEY_FALLBACK` values that were
synced through Yandex Disk (cloud storage). These keys should be considered
compromised.

Steps:
1. Go to <https://nvd.nist.gov/developers/request-an-api-key> and request two
   new API keys; revoke the old ones via the same portal.
2. Update `.env.local` with the new values.
3. Remove tracked binary/large files from git history:
   ```
   git rm --cached "deep-research-report(4).md"
   git rm --cached "Исследование контейнеризации, обновления баз и fallback-механизмов для cve-bin-tool, Trivy, Grype и .docx"
   git commit -m "chore: untrack research artefacts"
   ```

### 3.2  Real lockfile (NEW-3)

`requirements.lock` is a placeholder.  To produce the real one:
```sh
pip install pip-tools
pip-compile --strip-extras --generate-hashes -o requirements.lock requirements.in
```
Commit the result.  Until then the CI `pip install -r requirements.lock` step
installs `latest` and gives no reproducibility guarantee.
