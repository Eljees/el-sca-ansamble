GUI-дашборд с live-прогрессом, proxy-chain UI toggle.

**Активный фронт работ:** deploy-hardening — volume-init EACCES, последовательные
updater'ы, NVD feed fallback, DockerHub-теги, GitLab sync.

## 4. Выявленные дефекты

### D-290-1 (P2) — 6 файлов в `artifacts/` не покрыты `.gitignore`

**Проблема:** `git status` всегда показывает `?? artifacts/`, создавая иллюзию
незакоммиченной работы там, где её нет. При `git add .` эти файлы случайно попадут
в коммит.

**Затронутые типы:**

| Паттерн | Примеры | Нужно добавить в .gitignore |
|---|---|---|
| `.done`-маркеры | `grype-active.done` | `artifacts/*.done` |
| container-ID scratch | `_local_*.txt` | `artifacts/_local_*.txt` |
| temp-скрипты | `_cmp_parse.py` | `artifacts/_*.py` |
| одноразовые отчёты | `COMPARISON_*.md` | `artifacts/COMPARISON*.md` (или `artifacts/*.md`) |

**Решение (простое):** добавить 4 строки в `.gitignore` в разделе artifacts.

**Альтернатива (более чистая):** заменить все пообъектные исключения на
`artifacts/**` + `!artifacts/.gitkeep` — но это требует аудита всех имеющихся
`!`-исключений (`.gitkeep` файлы уже удалены, так что исключения устарели).

### 5.1 Мелкий архитектурный замечание: volume-init pre-mkdir

В unstaged изменении `docker-compose.yml` создаётся 7 конкретных поддиректорий.
Риск: если структура отчётов изменится (например, появится `reports/syft`),
список нужно будет обновить вручную. Альтернатива — создавать поддиректории
из `run-scan.sh` при старте скана, а не из `volume-init`. Но текущий подход
проще и достаточен для v0.1.x.
