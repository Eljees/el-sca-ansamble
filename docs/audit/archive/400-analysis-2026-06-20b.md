### D13 — Windows atomic rename in `cve_db_audit.py` — CLOSED

**Root cause:** The Windows `PermissionError` fallback in `activate_best_cve_bin_tool_db`
used `shutil.copytree(active→previous) + shutil.rmtree(active) + shutil.move(staging→active)`.
Between `rmtree(active)` and the subsequent move, `active_path` was absent for potentially
several seconds (6 GB DB copy) — a race window for any reader assuming `active/` always exists.

**Fix:** Extracted `_win_activate_fallback()` in `resilient_updates/cve_db_audit.py`:

1. `os.replace(active_path, previous_path)` — atomic `MoveFileExW` on same volume, zero gap
2. `os.replace(staging_dir, active_path)` — atomic promotion; rollback on failure
3. `OSError`/`EXDEV` fallback to original `shutil.copytree`+`rmtree` for cross-device edge case

The inline fallback block in `activate_best_cve_bin_tool_db` now delegates to this function.

**Coverage:** 5 new tests in `tests/test_cve_db_audit.py`:
- `test_win_activate_fallback_uses_os_replace`
- `test_win_activate_fallback_cross_device_falls_back_to_copy`
- `test_win_activate_fallback_restores_active_on_staging_move_failure`
- `test_win_activate_fallback_no_active_no_error`
- `test_activate_best_windows_permission_error_uses_fallback`
