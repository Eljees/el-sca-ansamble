## 3. Новые наблюдения

### D_NEW-1 — docker-compose.yml: hardcoded image tag `0.1.1` (ЗАКРЫТ в этом прогоне)

**Обнаружено:** Все 12 строк `image: elariaphd/el-sca-*` в `docker-compose.yml`
использовали захардкоженную версию `0.1.1`:

```
image: elariaphd/el-sca-resilient-updater:0.1.1   # × 9
image: elariaphd/el-sca-extractor:0.1.1            # × 1
image: elariaphd/el-sca-cve-bin-tool:0.1.1         # × 2
image: elariaphd/el-sca-apk-analyzer:0.1.1         # × 1
image: elariaphd/el-sca-win-analyzer:0.1.1         # × 1
```

`versions.env` содержит `EL_SCA_VERSION=0.1.4` и явно предписывает:
> _"When you bump a version here, also update: docker-compose.yml fallback to match"_

**Последствие:** При `docker pull` (деплой без пересборки) скачивается образ `0.1.1`,
а не текущий `0.1.4`. Расхождение незаметно при `docker compose build`, но критично
при airgap-деплое с pre-built images.

**Исправление (P3, применено):**
Все 12 строк заменены с `:0.1.1` → `:${EL_SCA_VERSION:-0.1.4}`.
Теперь compose подхватывает версию из `versions.env` (через `--env-file`) или
использует `0.1.4` как дефолт.

```
image: elariaphd/el-sca-resilient-updater:${EL_SCA_VERSION:-0.1.4}
```

### D_NEW-2 — Нет CI-проверки синхронизации версий (backlog)

**Обнаружено:** CI не содержит job, который сравнивает:
- `EL_SCA_VERSION` из `versions.env`
- fallback-версию в `docker-compose.yml`
- `version` из `pyproject.toml`

Как следствие — рассинхронизация (D_NEW-1) могла существовать незаметно.

**Предлагаемое исправление (P3, backlog):**
Добавить в `.github/workflows/ci.yml` шаг `lint-versions`:

```yaml
lint-versions:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - name: Check version consistency
      run: |
        set -e
        EL_VER=$(grep '^EL_SCA_VERSION=' versions.env | cut -d= -f2)
        PY_VER=$(grep '^version = ' pyproject.toml | sed 's/version = "\(.*\)"/\1/')
        DC_VER=$(grep -oP 'elariaphd/el-sca-[^:]+:\K[0-9]+\.[0-9]+\.[0-9]+' docker-compose.yml | sort -u)
        echo "versions.env: $EL_VER  pyproject.toml: $PY_VER  docker-compose.yml: $DC_VER"
        [ "$EL_VER" = "$PY_VER" ] || { echo "VERSION MISMATCH: versions.env vs pyproject.toml"; exit 1; }
        [ -z "$DC_VER" ] || echo "INFO: docker-compose.yml still has hardcoded fallback $DC_VER (expected via \${EL_SCA_VERSION})"
```

### A_OBS-1 — `_probe_layer` (healthcheck.py): 9 позиционных аргументов (backlog P3)

`_probe_layer` принимает 9 аргументов вместо того, чтобы принять `RetryPolicy` напрямую:

```python
def _probe_layer(config, tool, layer, timeout, retry_count, backoff_seconds,
                 retry_status_codes, non_retryable_reasons=None, session=None)
```

`run_healthcheck` уже конструирует `RetryPolicy` объекты (`trivy_retry`, `grype_retry`,
`cve_retry`), а затем распаковывает их полями вручную. Логично передавать `policy`
напрямую:

```python
def _probe_layer(config, tool, layer, *, timeout, policy: RetryPolicy, session=None)
```

**Приоритет:** P3 backlog (нет функционального дефекта, только API-усложнённость).
Сейчас не меняем — изменение сигнатуры ломает `test_healthcheck.py`, требует
согласованного PR.
