### A2 (FIXED, P3) — call sites не передают `non_retryable_reasons` в `attempt_sources`

**Суть проблемы:**
Коммит `bd27371` добавил `non_retryable_reasons` в `RetryPolicy.as_attempt_kwargs()`,
но три вызова `attempt_sources` в `vex.py`, `cli.py` и `healthcheck.py` по-прежнему
передавали поля вручную, пропуская `non_retryable_reasons`. Это означало, что `attempt_sources`
всегда падал назад на модульную константу `_NON_RETRYABLE_REASONS` — функционально
эквивалентно, но архитектурно противоречит цели A2.

**Реализованные правки:**

**`resilient_updates/vex.py`:**
```python
# До:
candidate, payload, attempts = attempt_sources(
    [source],
    timeout=int(retry.timeout_seconds),
    retry_count=retry.retry_count,
    backoff_seconds=int(retry.backoff_seconds),
    retry_status_codes=list(retry.retry_status_codes),
    session=session,
)
# После:
candidate, payload, attempts = attempt_sources(
    [source],
    **retry.as_attempt_kwargs(),
    session=session,
)
```

**`resilient_updates/cli.py` — `_health_summary`:**
- Добавлен параметр `non_retryable_reasons: frozenset[str] | None = None`.
- `attempt_sources` теперь получает `non_retryable_reasons=non_retryable_reasons`.
- Оба вызова `_health_summary` (trivy и cve_bin_tool) передают `non_retryable_reasons=<tool>_retry.non_retryable_reasons`.

**`resilient_updates/cli.py` — `update_grype` → `attempt_sources`:**
- Добавлен `non_retryable_reasons=grype_retry.non_retryable_reasons`.

**`resilient_updates/healthcheck.py` — `_probe_layer`:**
- Добавлен параметр `non_retryable_reasons: frozenset[str] | None = None`.
- `attempt_sources` теперь получает `non_retryable_reasons`.
- Все вызовы `_probe_layer` (trivy через `**trivy_kwargs`, grype, cve_bin_tool) передают `non_retryable_reasons`.

**Backward-compat:** `non_retryable_reasons=None` → `attempt_sources` падает на
`_NON_RETRYABLE_REASONS` — поведение при `None` не изменилось.
