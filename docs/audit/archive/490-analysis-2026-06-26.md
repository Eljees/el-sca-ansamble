### 3.3 PROVENANCE-COVERAGE — граница gate

**Файл:** `resilient_updates/provenance.py`.
**Покрытие:** 88% (gate = 88%, на границе).

Непокрытые строки 8–11 — ветка `except ImportError:` (fallback для Python < 3.11):
```python
try:
    from datetime import UTC  # py3.11+
except ImportError:
    from datetime import timezone as _tz
    UTC = _tz.utc  # noqa: UP017  ← строки 8-11, не покрыты на py3.14
```

Аналогичный паттерн встречается в 14 других модулях. На dev-машине Python 3.14, поэтому `except ImportError` никогда не выполняется.

**Оценка:** Не дефект. Fallback-код корректен и нужен, пока `requires-python = ">=3.10"`. Риска нет. Но если coverage-gate когда-нибудь поднять выше 88%, эта ветка подпадёт под исключение или потребует `# pragma: no cover`.

**Приоритет:** P4 (информация, действие не требуется сейчас).

**Деферированное действие:** При будущем bump min-version до 3.11 — удалить все `try/except ImportError` для `datetime.UTC` (~15 модулей). Это чистый one-shot коммит.

### 3.5 Наблюдение: Python 3.10 compat shims повсюду

Паттерн:
```python
try:
    from datetime import UTC  # py3.11+
except ImportError:
    from datetime import timezone as _tz
    UTC = _tz.utc
```
Встречается в 15 модулях (`artifact_store.py`, `cli.py`, `cve_db_audit.py`, `enrichment.py`, `extractor.py`, `manifest.py`, `nvd_feed_import.py`, `pipeline_state.py`, `provenance.py`, `proxy_chain.py`, `route_plan.py`, `run_layout.py`, `run_summary.py`, `vex.py`) + `fallback.py` использует `# noqa: UP042` для `StrEnum`.

Это намеренно и правильно — `requires-python = ">=3.10"`. Но это создаёт «замороженную» зону tech-debt: как только минимальная версия будет поднята до 3.11, все эти shims можно удалить автоматически (`ruff --fix` сделает большую часть).

**Рекомендация (не срочно):** Добавить в backlog задачу «bump requires-python to >=3.11, remove compat shims» с пометкой «безопасно делать в любой момент».
