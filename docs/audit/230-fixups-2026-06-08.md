## 1. Найденные и исправленные дефекты

### D-NEW-1: `datetime.UTC` bare import — CI блокер на Python 3.10

**Severity:** CRITICAL (блокирует сбор тестов на Python 3.10)

**Проблема:** Два модуля использовали голый `from datetime import UTC, datetime` без
compat-шима:

- `resilient_updates/nvd_feed_import.py:53`
- `resilient_updates/vex.py:18`

`datetime.UTC` появился только в Python 3.11. Остальные 10 модулей в проекте уже используют
корректный паттерн:
```python
try:
    from datetime import UTC  # py3.11+
except ImportError:
    from datetime import timezone as _tz
    UTC = _tz.utc  # noqa: UP017
```

Этот дефект полностью ломал `pytest --collect` на Python 3.10 (`ImportError` при импорте
`test_nvd_feed_import.py`), что означает что CI-матрица для Python 3.10 **не собирала ни
одного теста**.

**Диагностика:** Усложнена FUSE-mount кэшированием — bash-окружение показывало
устаревшую версию файла с matching mtime в .pyc. Изменения верифицированы через Read tool
(Windows-сторона) и Desktop Commander.

**Фикс:** Применён стандартный compat-шим в обоих файлах. Коммит `e9c6d44`.

## 5. Технические наблюдения

**FUSE-mount mtime staleness:** При редактировании через Windows-путь (`D:\dev\...`)
bash-окружение видит старый контент с совпадающим mtime (embedded в .pyc == mtime файла).
`touch` помогает сбросить кэш, но если файл является syntax-invalid — Python просто
падает с SyntaxError (FUSE обрезает файл). Рабочий обход: Desktop Commander для
git/python-операций, Read tool для верификации Windows-стороны.
