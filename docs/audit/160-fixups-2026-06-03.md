## 2. Fixes applied this pass

### 2.1 Deduplicate `_normalize_severity` into `_io.py` (P3, FIXED)

**Problem:** `_normalize_severity` was defined identically in both
`reporting.py` and `scanner_diff.py`.  A future change (e.g. mapping
vendor-specific severity strings) would have to be made in two places with
no compile-time guarantee they stay in sync.

**Fix applied:**

1. Added `normalize_severity(value: Any) -> str` to
   `resilient_updates/_io.py` (the existing shared low-level helpers module)
   with a full docstring referencing this audit.

2. Updated `resilient_updates/reporting.py` import block:
   ```python
   # before
   from ._io import (
       read_json as _read_json,
       sha256_dir as _sha256_dir,
       sha256_file as _sha256_file,
   )
   # after
   from ._io import (
       normalize_severity as _normalize_severity,
       read_json as _read_json,
       sha256_dir as _sha256_dir,
       sha256_file as _sha256_file,
   )
   ```
   Removed the local `def _normalize_severity` body.  The module-level alias
   `_normalize_severity` is preserved so `test_reporting_helpers.py`
   (`from resilient_updates.reporting import _normalize_severity`) continues
   to work without modification.

3. Updated `resilient_updates/scanner_diff.py`: added
   `from ._io import normalize_severity as _normalize_severity`, removed
   the local function body.

**Verification (Read tool — Windows filesystem):**
- `_io.py` lines 161–172: `normalize_severity` present and correct.
- `reporting.py` lines 9–14: import alias in place; no local def between
  `target_digest` and `_syft_count`.
- `scanner_diff.py` lines 36–37: both `_io` imports present; no local def.
