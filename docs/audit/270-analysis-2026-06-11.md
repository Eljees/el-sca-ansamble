**Версия:** v0.1.0 (с 2026-06-06). Активная разработка. CI на GitHub Actions + GitLab.

## 2. Выявленные дефекты

### D-NEW-1 (P2) — `.gitkeep` файлы удалены с диска, но не закоммичены

Шесть `.gitkeep`-плейсхолдеров были удалены с диска, но `git rm` не выполнялся:
```
 D artifacts/.gitkeep
 D artifacts/cache/.gitkeep
 D artifacts/mirror/.gitkeep
 D artifacts/provenance/.gitkeep
 D artifacts/reports/.gitkeep
 D artifacts/sbom/.gitkeep
```
Из-за этого `git status` всегда «грязный» — даже когда никакой реальной работы нет.
Эти файлы были нужны для отслеживания пустых директорий в git. Сейчас директории
содержат runtime-артефакты (gitignored), поэтому `.gitkeep` больше не нужны.

**Решение:** закоммитить удаления через `git rm`.

---

### D-NEW-2 (P1-архитектура) — `POST /api/proxy-chain` мутирует git-отслеживаемый файл

`dashboard.py:849+` записывает новое значение `default_chain` напрямую в
`configs/feed_sources.yaml`. Этот файл отслеживается git. Последствия:

1. После первого переключения прокси в UI — `git status` постоянно показывает `M configs/feed_sources.yaml`.
2. Текущее состояние: `default_chain: via-vpn` (runtime-значение) попало в working tree.
3. При случайном `git add .` runtime-состояние уйдёт в коммит.
4. При `git pull` / merge возможен конфликт, если в remote был другой дефолт.

Это was noted in pass 260. Требует архитектурного решения (см. план).

---

### D-OLD-1 (P3, carry-forward) — Windows atomic rename в `cve_db_audit._activate`

`shutil.move` не атомарен на NTFS для 6+ GB файлов. Нужен `MoveFileExW` через ctypes.
Открыт с pass 240. Сложность высокая, не блокирует Linux-продакшен.

## 4. Архитектурные недостатки

### 4.1 Нет разделения static vs runtime конфигурации прокси

`configs/feed_sources.yaml` одновременно является:
- источником истины для настройки прокси-цепочек (static, в git)
- местом хранения текущего выбора цепочки (runtime, изменяется через API)

**Рекомендация:** ввести `configs/feed_sources.runtime.yaml` (gitignored) для runtime state.
API читает runtime-файл, откатывается на static defaults.

### 4.2 Нет `--cov-fail-under` в CI

Регрессии покрытия тестами не блокируют pipeline. Покрытие может тихо упасть.

### 4.3 Нет маркировки интеграционных тестов

Тесты, требующие Docker (Docker socket, реальные контейнеры), не помечены
`@pytest.mark.integration`. Невозможно быстро запустить только unit-тесты.

### 4.4 Статические аудит-документы устарели

`docs/audit/00-overview.md`, `10-defects.md`, `20-architecture.md`, `30-tests.md`
датированы 2026-05-25 (коммит `7a04438`). С тех пор закрыты D1–D12, добавлены
100+ тестов, появились новые модули (nvd_feed_import, vex, proxy_chain и др.).
Новый разработчик, читая эти файлы, получает неактуальную картину.

### 4.5 CHANGELOG [Unreleased] пуст

С момента v0.1.0 добавлены существенные функции:
- proxy-chain API + UI toggle (`dashboard.py`)
- NVD feed channel (`nvd_feed_import.py`)
- GUI «бочки» для обновления баз
- Ubuntu install path (`docs/ubuntu-from-github.md`)

Ни одна из них не задокументирована в `CHANGELOG.md [Unreleased]`.

### 4.6 scripts/ содержит мусор и дубли

30+ скриптов в `scripts/`. Часть из них устарела или одноразова:
- `reproduce-cybersec-11531.sh` — тикет-специфичный, скорее всего больше не актуален
- `benchmark.sh` — утилита разработки без документации
