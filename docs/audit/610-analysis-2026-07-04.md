## 4. Новые наблюдения (без правок)

### 4.1 compose-config CI gap (P4)

`ci.yml` job `compose-config` проверяет только `base` + `windows.override`.
`docker-compose.linux.override.yml` и `docker-compose.offline.yml` не проверяются.
При несовместимом изменении в этих файлах CI не поймает проблему.

**Предложение**: добавить два шага в `compose-config`:
```yaml
- name: docker compose config (linux overlay)
  run: docker compose -f docker-compose.yml -f docker-compose.linux.override.yml config -q
- name: docker compose config (offline overlay)
  run: docker compose -f docker-compose.yml -f docker-compose.offline.yml config -q
```

### 4.2 `_logging.py` — `format` затеняет builtin (P5, ruff --select=ALL)

`resilient_updates/_logging.py:102` — параметр функции `format: str | None = None`
затеняет Python builtin `format`. Текущий `.ruff.toml` это не запрещает (правило A002
не включено), поведение корректно, но стиль неидеальный.

**Предложение**: переименовать в `log_format` при следующей рефакторинге.

### 4.3 `scanner_diff.py` — готов к CLI интеграции (P3, SCANNER-DIFF-CLI)

350 LOC реализованы и покрыты тестами; CLI entry-point `scanner-diff` в `cli.py`
отсутствует. Добавление займёт ~30 LOC и сделает diff-функционал доступным без
прямого вызова `python -m resilient_updates.cli scanner-diff ...`.
