### 2.1 bandit B608 — nosec comment on wrong line [FIXED]

**File:** `resilient_updates/cve_db_audit.py`

```python
# Before (nosec on the cursor.execute() line, not the f-string line)

    f"SELECT data_source, COUNT(*) FROM {table_name} GROUP BY data_source"

```

bandit reports the finding at the f-string line (line 80), so the `# nosec B608`
on line 79 was silently ignored — the Medium finding remained visible in reports.

**Fix:** moved `# nosec B608` to the f-string line:

```python
cursor.execute(
    f"SELECT data_source, COUNT(*) FROM {table_name} GROUP BY data_source"  # nosec B608

```

**Result:** bandit Medium count: 1 → 0.

### 2.3 _collect_json naming clash in reporting.py [FIXED]

**File:** `resilient_updates/reporting.py`

`reporting._collect_json(root, names)` finds files by name via `rglob`, while
`_io.collect_json` reads a list of explicit paths — completely different semantics.
The shared prefix was causing confusion (audit-170 P5 carry-forward).

**Fix:** renamed `_collect_json` → `_find_json_by_name` throughout `reporting.py`
(function definition + all 5 call sites).  Added a docstring clarifying the
distinction from `_io.collect_json`.  No external callers; tests confirm no regression.

### 2.4 test_vex.py fails to collect on Python 3.10 [FIXED]

**File:** `tests/test_vex.py`

`vex.py` uses `from datetime import UTC` (Python 3.11+).  Individual test functions
had `pytest.mark.skipif(sys.version_info < (3, 11), ...)` marks, but those marks only
apply after the module is imported — they cannot prevent the `ImportError` at collection
time.  On Python 3.10 pytest errored during collection instead of skipping cleanly.

**Fix:** added a module-level guard immediately before the vex imports:

```python
if sys.version_info < (3, 11):
    pytest.skip("vex module requires Python 3.11+ (datetime.UTC)", allow_module_level=True)
```

**Verification note:** the NTFS FUSE mount does not propagate file-modification
timestamps back to the sandbox, so `tests/__pycache__/test_vex.cpython-310.pyc` retains
its original mtime and Python uses the old bytecode when running pytest in bash.
The fix is confirmed present via `cat` (line 20 = `if sys.version_info < (3, 11):`),
`linecache.getline`, and `py_compile.compile` (no error on py3.10).  It will take
effect after the stale pyc is regenerated — which happens on the Windows host (where
the mtime is updated correctly) or in CI (fresh checkout).
