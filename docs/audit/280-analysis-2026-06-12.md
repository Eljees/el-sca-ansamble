**Причина:** форматирование drift после редактирования через несколько инструментов

**Действие:** `ruff format` применён ко всем трём файлам. Тесты подтверждены зелёными.

### F-2026-06-12-2 — `build_update_command` без deprecation-примечания ✅ ИСПРАВЛЕНО

**Файл:** `resilient_updates/orchestrator.py` (строки 427–442)

**Проблема:** функция `build_update_command()` генерирует команду с
`up --abort-on-container-exit`, хотя реальный путь обновления (`start_update`)
уже использует последовательные `run --rm`-шаги. Функция не используется внутри
кода, но экспортируется — создаёт риск, что внешний вызывающий код использует
устаревший подход.

**Действие:** добавлен docstring `.. deprecated::` с объяснением нового подхода
и причины разделения.

### 5.3 Workflow: git через FUSE

FUSE-mount (/sessions/mnt/dev--el-sca-ansamble) имеет два системных ограничения:
1. **Stale inode**: файлы, изменённые через Windows-инструменты (Edit, Desktop
   Commander), могут показывать старый контент в bash до принудительного
   переписывания через новый inode.
2. **git timeout**: `git status`/`git log` зависают из-за повреждённого
   pack-объекта (`error: improper chunk offset(s) e30 and 200c`). Все git-операции
   нужно выполнять из Windows.

**Обходной путь (задокументирован в memory):** создать Windows-inode через
`Write` → `cat fresh > original` из bash.
