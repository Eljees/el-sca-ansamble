### 3.4 PYCACHE-STALE — 279 стейл-.pyc файлов (P5, локальный мусор)

На dev-машине (Python 3.14) в `__pycache__/` накопились файлы от трёх интерпретаторов:

| Директория | Всего .pyc | Стейл (3.10 + 3.12) |
|---|---:|---:|
| `resilient_updates/__pycache__/` | 90 | 60 |
| `tests/__pycache__/` | 261 | 217 (approx) |
| `scripts/__pycache__/` | 3 | 2 |
| **Итого** | **354** | **~279** |

Файлы не в git (`.gitignore: __pycache__/`, `*.pyc`). Вреда не несут, но:
- Увеличивают объём YandexDisk-синхронизации (YD синхронизирует всё что не в `.gitignore`
  *там* — но `.gitignore` не транслируется в правила YD. Если папка не в YD-exclude, эти
  279 файлов синхронизируются в облако лишний раз при каждом перестроении).
- FUSE-stale записи по ним увеличивают вероятность побочных эффектов (см. FUSE-DOCS в 610).

**Очистка** (команда, не выполнять без ОК):
```sh
find . -path "*/__pycache__/*.pyc" ! -name "*.cpython-314.pyc" -delete
```
Или через pytest:
```sh
python -m pytest --cache-clear -q --collect-only > /dev/null 2>&1
find . -path "*/__pycache__/*.pyc" -not -name "*314*" -delete
```

Риск: нулевой — Python пересоберёт нужные файлы при следующем импорте.
