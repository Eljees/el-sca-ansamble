## 3. Обнаруженный и исправленный дефект: CI-LINUX-INTERNALERROR

### 3.1 Симптом

При запуске полного suite (`pytest tests/`) на Linux-хосте (включая GitHub CI
`ubuntu-latest`) тест `test_activate_best_windows_permission_error_uses_fallback`
в `tests/test_cve_db_audit.py` вызывал `INTERNALERROR` вместо нормального
сообщения о падении:

```
INTERNALERROR> NotImplementedError: cannot instantiate 'WindowsPath' on your system
```

Ошибка происходила в **pytest-репортере** при попытке отформатировать трейсбек
упавшего теста, после чего результаты всего прогона терялись.

### 3.2 Корневая причина

Тест вызывал `monkeypatch.setattr(_mod.os, "name", "nt")`, которое **глобально**
меняет атрибут модуля `os`. В Python 3.10, когда `os.name == 'nt'`, вызов
`pathlib.Path(anything)` пытается создать `WindowsPath`:

```python
# cpython/Lib/pathlib.py:
def __new__(cls, *args, **kwargs):
    if cls is Path:
        cls = WindowsPath if os.name == 'nt' else PosixPath
    self = cls._from_parts(args)
    if not self._flavour.is_supported:   # always False on Linux
        raise NotImplementedError(...)
```

`_windows_flavour.is_supported` вычисляется **при импорте** (`= os.name == 'nt'`) и
на Linux всегда `False`. Значит `Path()` падает с `NotImplementedError` на
протяжении всего теста, где `os.name` перезаписан.

Производственный код внутри `activate_best_cve_bin_tool_db` вызывает
`active_path = Path(active_root)` — тест падал сразу же. Pytest пытался
форматировать ошибку, снова вызывал `Path(os.getcwd())` (в `_repr_failure_py`)
и получал второй `NotImplementedError`, приводя к `INTERNALERROR`.

Дефект присутствовал с коммита `2d801a0` (2026-06-20) и дошёл до `origin/master`
в `12395c9` (2026-06-23), то есть **CI ubuntu-latest был сломан ~12 дней**.

### 3.3 Исправление

В `resilient_updates/cve_db_audit.py` добавлен тонкий хелпер:

```python
def _is_windows() -> bool:
    """Return True when running on Windows. Extracted so tests can patch it without
    touching os.name globally (patching os.name breaks Path() on Linux)."""
    return os.name == "nt"
```

Инлайн-проверка заменена вызовом хелпера:

```python
    except PermissionError:
        if not _is_windows():   # было: if os.name != "nt":
            raise
        _win_activate_fallback(staging_dir, active_path, previous_path)
```

В тесте `monkeypatch.setattr(_mod.os, "name", "nt")` заменён на:

```python
monkeypatch.setattr(_mod, "_is_windows", lambda: True)
```

`os.name` остаётся `'posix'` на Linux → `Path()` работает корректно.

## 4. Прочие находки (не требуют правок)

### 4.1 FUSE stale-mount — подтверждено

При работе через FUSE-монтирование (sandbox → D:\dev):
- `mtime` файлов не обновляется после редактирования через Windows
- Python видит stale `.pyc` как более свежий и использует его
- `git diff` тоже не видит изменений (stale inode cache)

Обход: запускать git и pytest через Desktop Commander (Windows-native процесс).
Документировать в `docs/CONTRIBUTING.md` как известное ограничение.
