## 3. Новые находки

### 3.1 FUSE-TRUNC-RECURRENCE — пятое повторение обрезания

Это уже пятое зафиксированное событие FUSE-обрезания за две недели (610 = 4-е).
Паттерн стабилен: YandexDisk-синхронизация обрезает файлы по границе сетевого
пакета/блока при конкурентном чтении. Текущая стратегия — обнаружение через `git diff`
и ручное/автоматическое восстановление из git HEAD — работает, но требует внимания
при каждом запуске.

**Предложение (FUSE-GUARD)**: добавить в scheduled-task preflight шаг:
```sh
git diff --name-only | xargs -I{} git checkout HEAD -- {} 2>/dev/null || true
```
Это восстановит все FUSE-обрезанные файлы автоматически до начала анализа.

_Примечание_: восстановление через `git checkout HEAD --` из bash внутри sandbox
всё ещё не работает (FUSE unlink), но аналог через Windows PowerShell (`git restore`)
— работает. Preflight можно реализовать через Windows MCP.

### 3.2 GIT-INDEX-LOCK-RECURRENCE — стейл lock от 03 июля

`.git/index.lock` (создан 2026-07-03, 0 байт) блокировал все `git add` из bash-sandbox.
Удалён через `mcp__Windows-MCP__PowerShell`. В bash через `rm` не удалялся (FUSE
permission). Это та же FUSE-аномалия: `ls -la` возвращал "No such file or directory",
`stat` — видел файл.

**Предложение (LOCK-CLEANUP)**: добавить в scheduled preflight:
```powershell
$lk = "D:\dev\el-sca-ansamble\.git\index.lock"
if ((Test-Path $lk) -and (Get-Item $lk).Length -eq 0) { Remove-Item -Force $lk }
```
