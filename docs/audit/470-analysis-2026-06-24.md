## 3. Новые находки

### A_OBS-2 — `_health_summary` в `cli.py` всё ещё принимает 4 отдельных retry-параметра

**Файл:** `resilient_updates/cli.py:211–251`

**Что было:** A_OBS-1 упростил `_probe_layer` (`healthcheck.py`) — теперь принимает `retry: RetryPolicy`. Но `_health_summary` (CLI-обёртка аналогичного назначения) по-прежнему имеет сигнатуру:

```python
def _health_summary(
    config, tool, layer, timeout,
    retry_count: int,
    backoff_seconds: int,
    retry_codes: list[int],
    non_retryable_reasons: frozenset[str] | None = None,
    session=None,
) -> tuple[int, dict[str, Any]]:
```

**Два call-site (строки 979–993 и 997–1010)** вручную распаковывают `RetryPolicy` в 4 отдельных kwarg:

```python
# cli.py:981–991 — update trivy
trivy_retry = RetryPolicy.from_tool_config(config, "trivy")
code, payload = _health_summary(
    config, "trivy", "trivy-db",
    timeout=int(config["trivy"]["source_health_policy"]["healthcheck_timeout_seconds"]),
    retry_count=trivy_retry.retry_count,
    backoff_seconds=int(trivy_retry.backoff_seconds),
    retry_codes=list(trivy_retry.retry_status_codes),
    non_retryable_reasons=trivy_retry.non_retryable_reasons,
    session=_session,
)
```

**Что сделать:** изменить сигнатуру `_health_summary` на `retry: RetryPolicy`, обновить тело и два call-site. Аналогично тому, что было сделано для `_probe_layer` в A_OBS-1.

**Приоритет:** P3 (рефакторинг, не баг).
