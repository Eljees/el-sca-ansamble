## 3. D10 — resolved by design

The apparent conflict between `_NON_RETRYABLE_REASONS` and `retry_status_codes` is
intentional: `_NON_RETRYABLE_REASONS` contains `AUTH_FAILURE` and `INVALID_SCHEMA` as
permanent error categories that should never be retried regardless of HTTP code.

`HTTP_4XX` is also in `_NON_RETRYABLE_REASONS` to make the common case fast (most 4xx
responses are permanent).  The `status_code not in retry_status_codes` guard handles
the case where a user wants to retry a specific 4xx code (e.g. 429 Too Many Requests):
by placing 429 in `retry_status_codes` the code bypasses the inner loop's early-exit.

The test suite (`tests/test_fallback_order.py:test_auth_failure_403_is_not_retried`)
explicitly documents and verifies this: even with `retry_status_codes=[403]`, an
`AUTH_FAILURE` reason stops retrying — by design, to avoid infinite auth loops.

**Conclusion:** No code change needed.  Adding a docstring note to `_NON_RETRYABLE_REASONS`
would clarify the interaction for future readers; deferred to a documentation-only pass.

## 4. D13 — Windows activation race (remaining exposure)

`cve_db_audit._activate` Windows fallback path (lines 353–365):
1. `shutil.copytree(active → previous)` — backup
2. `shutil.rmtree(active)` — **window opens here**
3. `shutil.move(staging → active)` — window closes

Between steps 2 and 3 any scan process reading `active_path` sees a missing directory.
For cve-bin-tool DB (~6 GB) `shutil.move` across an NTFS volume takes seconds.

A proper fix would write to `active.new`, then use `os.replace`-style rename.  This
requires OS-specific rename semantics on Windows (no `os.rename` across directories;
would need `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`).  The fix is non-trivial and
carries regression risk — deferred to a targeted Windows-runtime pass.
